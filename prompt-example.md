# Example Troubleshooting Prompt

> I am building a beginner-friendly Python 3.12 command-line tool for synthetic transaction data. Use only the standard library. The CSV columns are transaction_id, customer_id, amount, status, and timestamp. Allowed statuses are COMPLETED, PENDING, and FAILED. Amounts must be finite and nonnegative; zero is permitted. Required fields cannot be blank. Timestamps must parse as ISO format. Report later occurrences of duplicate nonempty transaction IDs without modifying the source data. For A, B, A, expect one duplicate occurrence. Report every issue on a row, including malformed or missing amounts and wrong column counts. Produce duplicates.csv, invalid_records.csv, and summary.json. Explain assumptions, failure behaviour, time and memory complexity, and edge cases. Keep functions short enough for a fresh graduate to explain. First suggest an approach, then provide code and independently understandable test cases. Do not introduce external services or credentials.

This prompt gives context, a data contract, explicit duplicate semantics, output expectations, constraints, and a known example. Follow up with actual observed output and a small synthetic failing input if behaviour differs. Review the answer against the [validation checklist](validation-checklist.md).
